# Repository Cache-first  💻️

**Repository Cache-first** - Виконання практичного завдання **Залікового білету №7** з дисципліни **"Розробка проблемно-орієнтованих мов програмування для
мобільних та ігрових застосунків"**.

## 📋 Умова практичного завдання

Реалізуйте у Kotlin клас TaskRepository з Cache-first логікою:

- поле private val cache = mutableListOf()

- suspend fun getTasks(): List: якщо cache не порожній - повернути cache інакше - "завантажити" з мережі (return listOf("Задача 1","Задача 2")), зберегти у cache, повернути результат

- suspend fun refresh(): оновити cache з мережі незалежно від кешу

## ✔️ Результати виконання

app/src/main/java/com/example/repositorycachefirst/repository/TaskRepository.kt - **(Repository патерн)** - Реалізація **Repository** із стратегією синхронізації **Cache-first** *(імітація)*:

1. **Інкапсуляція кешу (private val cache)** - Змінна cache оголошена як private та є змінним списком (mutableListOf). Це означає, що додавати або видаляти елементи можна лише всередині TaskRepository. Коли методи повертають результат, вони використовують .toList(). Це створює незмінну (immutable) копію списку, що гарантує: зовнішній код (наприклад, ViewModel) не зможе випадково змінити стан кешу напряму.
2. **Метод getTasks() (Cache-first логіка)** - Цей метод спочатку перевіряє, чи порожній кеш (cache.isEmpty()).
    * Якщо **не порожній** — мережевий запит ігнорується, і відразу повертаються збережені дані. Це суттєво економить ресурси та пришвидшує роботу застосунку.
    * Якщо **порожній** - викликається приватна функція імітації мережевого запиту fetchFromNetwork(), а отримані дані записуються в кеш.
3. **Метод refresh()** - Ця функція потрібна для реалізації **Pull-to-refresh** або для фонової синхронізації. Вона навмисно ігнорує перевірку на порожнечу і завжди робить мережевий запит, після чого повністю перезаписує старий кеш новими даними.
4. **Допоміжні методи** - Логіка завантаження з мережі **(fetchFromNetwork)** та оновлення списку **(updateCache)** винесена в окремі приватні функції, щоб уникнути дублювання коду в методах getTasks() та refresh().
5. **Корутини (suspend)** - Методи getTasks, refresh та fetchFromNetwork позначені модифікатором **suspend**. Це обов'язкова умова для **асинхронного програмування** в Kotlin, оскільки робота з мережею не повинна блокувати головний потік виконання програми. У коді також використано delay(500), щоб зробити імітацію мережевої затримки.
